# postman-api-test-demo
手工接口测试练习项目
测试接口：Reqres 用户接口
使用工具：Postman、Excel

## 项目做了什么
我自己对Reqres的用户接口做手工测试，按照测试方法设计用例，一个个在Postman发请求执行，对比预期和实际返回结果，把发现的问题写成缺陷记录。

## 测了这4个接口
- GET /api/users/{id}：查询单个用户
- GET /api/users?page：分页查用户列表
- POST /api/users：新建用户
- PUT /api/users/{id}：修改用户信息

## 怎么设计的用例
用到等价类、边界值、场景法：
1. 正常场景：传合法参数，看接口能不能正常返回数据
2. 异常场景：不传必填字段、传空请求体、ID写成字符串、查不存在的ID
3. 业务场景：先创建用户，用脚本拿到返回的id，再拿这个id去查询、更新，走一遍完整流程

一共写了12条测试用例，存在Excel里，记录请求参数、预期结果、实际结果、是否通过。

## 测出的问题
一共6个问题，全部写在bug_list.md里面：
1. 查询不存在的用户id=9999，返回404，但是没有错误提示文字
2. 创建用户的时候，不填name字段，接口依然能创建成功
3. 创建用户传空{}，接口不拦截，直接生成id
4. PUT更新，id填abc123这种字符串，接口直接返回成功，没有报错
5. PUT去更新一个不存在的用户id，也返回成功，容易误导前端
6. 这个是mock平台本身的限制：新建拿到id之后，再去查这个id会返回404，数据不会保存
